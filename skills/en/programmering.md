# Programming Task — Architectural Analysis

When planning a programming task:

## 1. Requirements Analysis
- Identify functional requirements: what should the system do?
- Identify non-functional requirements: performance, security, scalability
- Map inputs/outputs, use cases, and edge cases
- Note constraints (platform, language, third-party)

## 2. Architecture Design
- Design component breakdown and module structure
- Define data flow and interfaces between components
- Consider relevant design patterns (Factory, Singleton, Observer, etc.)
- Follow SOLID principles and separation of concerns
- Describe the architecture clearly before writing code

## 3. Implementation Plan
- List files to be created with purpose for each
- Implementation order (dependencies first)
- Test strategy: unit tests, integration tests
- Edge case and error handling

## 4. Security Analysis
- Follow OWASP best practices
- Input validation and sanitization
- Secure handling of credentials, keys, and passwords
- Encryption of sensitive data (at rest and in transit)
- Principle of least privilege
- Logging and audit trails

## 5. Code Implementation
- Write clean, maintainable code
- Use proper error handling (try/except, error codes)
- Document purpose of classes and functions
- Follow language conventions and the project's existing style
